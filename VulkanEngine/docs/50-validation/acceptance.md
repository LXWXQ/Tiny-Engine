# 验收标准与结果可信度

## 1. 什么算"通过"

一次改动只有在**下面全部成立**时才算通过：

| # | 判据 |
|---|---|
| 1 | 构建**零警告** |
| 2 | `tools/Validate.ps1` **20 项全 PASS** |
| 3 | 每项 **stderr 0 字节** |
| 4 | 每项 `[Validation] errors=0 warnings=0` |
| 5 | 涉及画质/性能时：`Baseline.ps1 -Action Diff` 无回归 |
| 6 | 涉及设计/行为时：对应文档已更新，`DocCheck.ps1` 通过 |

**不接受**的替代证据：

- "我手动跑了一下没崩"；
- "看起来画面正常"；
- "验证层没报错"（它抓不到语义问题——见下文 §3）。

## 2. 三条"结果可信度"规则

### 2.1 先拿噪声下限

**同构建连跑两次，排除 UI 面板后差异应该是 0.000。**

没有这个下限，就分不清"改动的效果"和"截图/测量的问题"。

> 真实案例：D-3 收尾时对比出"0.83% 像素不同"，差点当成回归。
> 实际原因是上一次的截图文件是旧的，那一轮窗口位置不同，把标题栏截了进去。

### 2.2 对比必须排除 ImGui 面板

面板尺寸会随代码变化，固定矩形排除会失效。现有做法是
`tools/Screenshot.ps1` 的 diff 只比右侧固定区域（"绝无可能是面板"的部分）。

### 2.3 均值漂移别当真

截图均值受**窗口位置**影响（窗口里 ImGui 面板占比不同）。
均值只能和"同一次会话、同一窗口位置"的图比。

## 3. 验证层的盲区

`[Validation] errors=0` **不等于**语义正确。以下问题验证层一言不发：

| 问题类型 | 例子 |
|---|---|
| 瞬时资源没人写 | SSAOPass 被跳过，`lighting.frag` 无条件采样它 |
| 逻辑错误 | 矩阵乘反、UV 翻转错、阈值算错 |
| 资源泄漏 | 析构顺序错（VMA 断言只在退出时爆） |
| 性能退化 | 少了几个 pass / 多了几次全屏 |

前两条只能靠**渲染图的语义校验**（W2）和人工核对；后两条靠
`--gpu-timing` + `Baseline.ps1`。

## 4. 退出路径必须被覆盖

历史 bug：VMA 断言只在**析构**时触发，而当时的截图脚本用 `TerminateProcess`
杀进程——**根本不跑析构函数**。所以"验证层 0 字节"这个结论从未覆盖退出路径。

现在：

- `--selftest` 走正常退出路径（跑析构）；
- 交互式运行必须用 `WM_CLOSE` 让主循环自己退出，不能 `terminate()`。

## 5. 画面改动的验收流程

```powershell
# 1) 保存基线（改动前）
powershell -File tools/Baseline.ps1 -Action Save -Name before -Frames 150

# 2) 改代码、重建

# 3) 对比
powershell -File tools/Baseline.ps1 -Action Diff -Name before -Frames 150
```

输出三个维度：

| 维度 | 默认阈值 | 说明 |
|---|---|---|
| GPU 时间 | 单 pass 涨幅 > 25% **且** > 0.5ms 才告警 | 剔除前 30 帧预热 |
| 验证层 | warnings 不得增加 | errors 必须为 0 |
| 视觉 | mean diff <= 2.0 | 逐像素平均绝对差（0~255） |

## 6. 性能数字的可比性

- 只做**同机相对比较**，不跨机器。
- Debug 构建的数字不代表 Release。
- 必须剔除预热帧（`Baseline.ps1` 默认丢前 30 帧）——冷启动 GPU 升频会让头几十帧偏慢，
  不剔除会让基线系统性偏慢 20%~45%。
